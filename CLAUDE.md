# rssfeedz -- Feed Court RSS Aggregator

Popurls-style wall-of-text RSS aggregator. Live server (`server.py`) plus a cron
generated static snapshot. Only home-directory project with git version control.

## Commands

```bash
systemctl --user status rssfeedz    # live server, http://localhost:8111/
systemctl --user restart rssfeedz   # after editing server.py or index.html
journalctl --user -u rssfeedz -f    # per feed failures
python3 parsefeeds.py               # Static snapshot (static.html, jumble.html)
./feed.refresh.sh                   # Refresh static snapshot (cron, every 4 hours)
```

## Key Files

- `server.py` -- Live server: fetches feedlist.txt per request, serves index.html + /api/feeds
- `parsefeeds.py` -- Static snapshot generator, writes static.html and jumble.html
- `feedlist.txt` -- RSS feed URLs (one per line, `#` comments allowed)
- `index.html` -- Hand-written live page; renders /api/feeds client-side
- `static.html` -- Generated snapshot (cron), offline fallback
- `jumble.html` -- Generated randomized snapshot
- `feedcache.json` -- Last good copy of each feed, written by server.py
- `feedcourt.css` -- Styling
- `feedcourt.js` -- Client-side interactions
- `~/.config/systemd/user/rssfeedz.service` -- Unit that keeps the server running at login
- `backups/` -- Dated copies of the pre-live index.html
- `example.cron` -- Example cron configuration

## Output

- Live page: 4 hour cache, browser hard reload (Ctrl+Shift+R) or the refresh
  link forces a refetch, `?view=jumble` for the randomized column
- Static snapshot: auto-refresh meta tag (600s), regenerated by cron every 4 hours
- "More" expansion for each feed section
- Section headings show title plus short domain, e.g. `Deeplinks (eff.org)`

## Feed list rules

- one feed per source: `server.py` and `parsefeeds.py` dedupe on registrable
  domain, except reddit (per subreddit), youtube (per channel) and feedburner
  (per feed path)
- `site_domain()` strips scheme, `www`, and subdomains for headings

## Layout rules (index.html)

- text only by default: `IMAGE_OK` is an allow list, not a deny list. Only
  image-first and video-first sources (YouTube, Vimeo, photo feeds) render
  art; every news, tech, magazine and subreddit card carries no image and no
  row thumbnails
- video cards render on full rows of three, freshest first, and are capped to
  a multiple of three (`renderGrid`, `.rowbreak` forces the row break). Keep
  YouTube feeds in multiples of three: surplus feeds are held back rather
  than leaving a partial row, and a card row never mixes video with text
- YouTube Atom feeds return intermittent 404/500, so `fetch_bytes` retries
  `youtube.com/feeds` three times with backoff; expect channel gaps without it
- typography for readability: 17.5px body, near-white ink, secondary text
  never below `--dim`; colors and base size are the variables and `font:` line
  at the top of `feedcourt.css`

## Workflow

1. Edit feeds: modify `feedlist.txt`
2. Restart the service if you changed code, reload the page for new feeds
3. Static: `python3 parsefeeds.py`, open `static.html`
4. Automate: `feed.refresh.sh` in crontab (every 4 hours)
